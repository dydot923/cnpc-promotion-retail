## 1. 产品概述

### 1.1 产品定位

FuelSmart 是面向加油站便利店场景的一体化智能运营管理终端系统，通过多源数据融合（商品价格表、促销政策表、库存数量表），实现**智能促销结算、库存动态预警、AI营销物料生成**三大核心能力，解决传统收银系统在促销匹配效率、库存响应速度和营销物料产出周期上的痛点。

### 1.2 目标用户

| 用户群体 | 典型角色 | 使用场景 | 核心诉求 |
|---------|---------|---------|---------|
| 门店前台 | 收银员 | 日常收银结算 | 快速扫码、正确执行促销、零学习成本 |
| 门店管理 | 店长/副店长 | 运营管理、补货决策 | 库存一目了然、补货流程自动化、海报快速产出 |
| 区域运营 | 运营主管 | 多门店策略配置 | 促销政策统一配置、跨门店数据对比 |
| 系统维护 | IT管理员 | 系统部署与配置 | 数据导入、权限管理、系统稳定性 |

### 1.3 解决的核心问题

| 痛点 | 现状 | FuelSmart 解决方案 |
|------|------|--------------------|
| 促销结算慢、易出错 | 收银员凭记忆或翻阅纸质文件核对促销，复杂促销（满减叠加、组合购）经常遗漏或算错 | 条码扫描后自动匹配所有适用促销方案，直观展示价格对比，一键选择或跳过 |
| 库存管理滞后 | 依赖人工盘点，畅销品断货才发现，滞销品积压占用资金 | 实时监控库存与安全阈值，促销商品低库存强制弹窗预警，一键生成标准补货清单 |
| 营销物料产出慢 | 门店海报依赖设计部门，从需求提交到物料到位需数天 | 集成AI图像生成能力，选择促销活动后自动生成多风格候选海报，分钟级产出 |

## 4. 核心业务流程

### 4.1 智能结算流程

```
收银员扫描商品条码
        │
        ▼
┌─────────────────┐
│  条码输入/扫描枪  │ ← HID模式自动输入
└────────┬────────┘
         ▼
┌─────────────────┐     未找到      ┌──────────────┐
│  查询商品价格表   │ ────────────→  │ 提示"商品未录入"│
└────────┬────────┘                │ 手动输入或跳过  │
         │ 匹配成功                 └──────────────┘
         ▼
┌─────────────────┐
│  展示商品基本信息 │ → 名称、规格、零售价、会员价
└────────┬────────┘
         ▼
┌─────────────────┐     无促销       ┌──────────────┐
│ 查询促销政策表    │ ────────────→  │  按默认价格    │
│ 匹配所有适用促销  │               │  加入购物车    │
└────────┬────────┘                └──────────────┘
         │ 命中1~N条促销
         ▼
┌─────────────────────────────────┐
│  界面展示所有可选促销方案卡片      │
│  每张卡片显示:                    │
│  - 促销名称与类型标签             │
│  - 规则简述                      │
│  - 原价 → 实付价                 │
│  - 节省金额                      │
└────────┬────────────────────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌───────┐ ┌───────┐
│选择方案 │ │ 跳过   │
└───┬───┘ └───┬───┘
    │         │
    ▼         ▼
┌───────────────┐
│ 加入购物车     │ ← 记录: 商品、数量、适用促销、计算后单价
│ 更新小计/总计  │
│ 更新满减累计   │ ← 若有满减类促销，实时计算是否达标
└───────┬───────┘
        │
        ▼ (所有商品扫完后)
┌───────────────┐
│ 显示交易汇总   │ ← 商品合计、各优惠明细、优惠总额、应付金额
└───────┬───────┘
        ▼
┌───────────────┐
│ 确认结算       │ → 扣减库存 → 记录交易流水 → 清空购物车
└───────────────┘
```

**关键业务规则：**

- **促销优先级排序**：当同一商品命中多条促销时，按"节省金额从高到低"排列，同时标注"系统推荐"标签
- **满减跨商品累计**：满减类促销的金额统计基于同一笔交易内所有适用商品的累计金额，购物车实时更新进度（如"还差¥15.00即可减¥15"）
- **组合购校验**：若促销要求购买A+B组合，系统检测购物车中是否已包含组合所需商品，缺件时标注"再购XX即可享受"
- **会员价与促销价互斥规则**：默认取更低价展示；若促销配置为"与会员价叠加"则显示叠加后价格
- **促销时效校验**：每次匹配时校验当前时间是否在促销有效期内，过期促销自动排除
- **挂单/取单**：支持暂挂当前交易，处理下一位顾客后取回继续

### 4.2 库存预警与补货流程

```
┌──────────────────────────────┐
│  系统持续运行（前端轮询/事件驱动）│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│  比对库存数量表 vs 安全阈值     │
│  比对库存数量表 vs 促销关联商品  │
└──────────────┬───────────────┘
               │
        ┌──────┴──────┐
        ▼             ▼
   库存 ≥ 阈值    库存 < 阈值
     (正常)         │
                    ▼
          ┌─────────────────┐
          │ 判断预警级别      │
          │ critical: 库存≤阈值×20% │
          │ warning:  库存≤阈值     │
          └────────┬────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ 强制弹窗预警      │ ← 促销关联商品: 不可关闭，必须确认
          │ 展示:             │ ← 普通商品: 可关闭，但刷新前不重复弹出
          │ - 商品名称/条码   │
          │ - 当前库存/阈值   │
          │ - 预警级别        │
          │ - 是否参与促销    │
          │ - 建议补货数量    │
          └────────┬────────┘
                   ▼
          ┌─────────────────┐
          │ 操作员确认/修改   │ ← 可调整建议数量
          │ 补货清单          │
          └────────┬────────┘
                   ▼
          ┌─────────────────┐
          │ 一键生成表格      │
          │ - Excel(.xlsx)   │
          │ - CSV            │
          │ 含: 商品名/条码   │
          │   当前库存/阈值   │
          │   建议补货量      │
          │   紧急程度        │
          └────────┬────────┘
                   ▼
          ┌─────────────────┐
          │ 下载/发送         │
          │ 记录预警处置状态  │
          └─────────────────┘
```

**关键业务规则：**

- **建议补货量计算公式**：`建议补货量 = max(安全阈值 × 2 - 当前库存, 0)` ，可由管理员在系统设置中自定义公式
- **促销期间阈值自动提升**：当商品参与进行中的促销时，安全阈值自动乘以促销系数（默认1.5倍），提前预警
- **交易触发库存更新**：每笔结算完成后自动扣减库存，扣减后立即触发阈值检测
- **导入更新库存**：导入新库存表时全量覆盖当前库存数据，导入后触发一次全量阈值扫描
- **预警去重**：同一商品在同一预警周期（默认24小时）内不重复弹窗，但更新库存数值
- **库存来源优先级**：以最近一次导入的库存表为基准，结合交易扣减实时计算当前库存

### 4.3 AI海报生成流程

```
┌───────────────┐
│ 用户选择触发    │ ← 从促销列表选择/从库存预警关联跳转/直接进入
└───────┬───────┘
        ▼
┌───────────────┐
│ 选择目标促销    │ ← 下拉列表，展示所有进行中的促销
└───────┬───────┘
        ▼
┌───────────────────────────┐
│ 系统自动提取信息构建提示词   │
│ 提取: 商品名称、促销价格、   │
│ 促销类型、促销卖点           │
│ 拼接: 风格模板 + 商品信息    │
│      + 尺寸要求 + 质量标签   │
└───────┬───────────────────┘
        ▼
┌───────────────┐
│ 用户可选配置    │ ← 海报风格（醒目促销/简约现代/国潮/赛博）
│ (可选)         │ ← 尺寸规格（A4/A3/横幅/方形）
└───────┬───────┘
        ▼
┌───────────────┐
│ 展示AI提示词    │ ← 只读预览，高级用户可手动微调
│ (可编辑)       │
└───────┬───────┘
        ▼
┌───────────────────────────┐
│ 调用AI绘画API               │
│ - 发送提示词 + 参数          │
│ - 接收多张候选图片（4~6张）   │
│ - 超时/失败 → 提示重试       │
└───────┬───────────────────┘
        ▼
┌───────────────────────────┐
│ 网格展示候选海报             │
│ - 每张卡片带悬浮操作栏       │
│ - 操作: 下载 / 大图预览      │
│ - 标记: AI生成标签           │
└───────┬───────────────────┘
        │ 不满意？
        ▼
┌───────────────┐
│ 点击"换一批"   │ ──→ 重新调用API（相同提示词）
└───────────────┘
        │ 满意
        ▼
┌───────────────┐
│ 选择下载       │ → PNG/JPG 格式
│ (可选: 直接打印)│ → 连接本地打印机
└───────────────┘
```

**关键业务规则：**

- **提示词模板化**：系统内置多种风格模板，自动将商品信息注入模板生成最终提示词
- **生成历史保存**：每次生成结果（提示词+图片）保存到本地，供后续复用
- **失败重试**：AI API调用超时（默认30秒）或返回错误时，自动提示用户重试，不消耗额外配额
- **并发限制**：同一时间仅允许一个生成任务，防止API过载

```
│ - 全量覆盖：清空旧数据后导入 │

└───────┬───────────────────┘
        ▼
┌───────────────┐
│ 执行导入        │ → 写入数据库
│ 记录导入日志    │ → 时间/文件/条数/模式/操作人
└───────┬───────┘
        ▼
┌───────────────────────────┐
│ 导入后自动触发:             │
│ - 库存表导入 → 全量阈值扫描  │
│ - 促销表导入 → 生效校验      │
│ - 价格表导入 → 关联更新      │
└───────────────────────────┘
```

### 4.5 促销匹配算法概要

```
输入: 商品条码、当前时间、购物车已有商品列表、是否会员
                    │
                    ▼
           ┌────────────────┐
           │ Step 1: 筛选    │ 从促销表中筛选:
           │                │ - 适用商品范围包含该条码
           │ - 有效期包含当前时间
           │ - 促销状态 = 启用
           └───────┬────────┘
                   ▼
           ┌────────────────┐
           │ Step 2: 分类    │ 按促销类型分组
           │                │ - 单品特价/折扣
           │ - 买赠/买减
           │ - 组合购
           │ - 满减(跨商品)
           │ - 会员专享
           └───────┬────────┘
                   ▼
           ┌────────────────┐
           │ Step 3: 计算    │ 为每条促销计算:
           │                │ - 适用前提条件(数量/组合)
           │ - 实付价格
           │ - 节省金额
           │ - 均摊单价
           └───────┬────────┘
                   ▼
           ┌────────────────┐
           │ Step 4: 排序    │ 按节省金额降序排列
           │                │ 标注"推荐"标签(节省最多)
           └───────┬────────┘
                   ▼
           ┌────────────────┐
           │ Step 5: 输出    │ 返回方案列表给前端
           └────────────────┘
```

#### 5.2.2 促销类型与规则结构

| 促销类型 | 规则字段 | 匹配逻辑 | 结算计算 |
|---------|---------|---------|---------|
| 单品特价 | 固定特价金额 | 该商品参与 → 直接替换价格 | 数量 × 特价 |
| 单品折扣 | 折扣率（如0.85） | 该商品参与 → 原价×折扣率 | 数量 × 原价 × 折扣率 |
| 买赠 | 买N件赠M件 | 购买数量 ≥ N 触发 | floor(购买数 / (N+M)) × N × 单价 |
| 买减 | 买N件减X元 | 购买数量 ≥ N 触发 | 数量 × 单价 - floor(数量/N) × X |
| 组合购 | 组合商品列表 + 组合价 | 购物车包含所有组合商品 | 组合价 + 非组合商品原价 |
| 满减 | 门槛金额 + 减免金额 | 同一促销适用商品累计金额 ≥ 门槛 | 总金额 - floor(总金额/门槛) × 减免 |
| 会员专享 | 会员专用价格/折扣率 | 用户为会员 | 按会员规则计算 |

### 6.2 各页面详细交互设计

#### 6.2.1 数据概览页（Dashboard）

**页面构成：**

| 区域 | 内容 | 交互 |
|------|------|------|

| 销售趋势图（左侧大卡） | 本周每日销售柱状图 | 鼠标悬停显示具体数值 |

| 进行中促销（左下卡） | 活动列表，含类型标签和剩余天数 | 点击跳转促销详情 |

- 库存预警卡片中红色标记需有脉冲动画吸引注意
- 若有critical级库存预警且未处理，顶部通知铃铛显示红色角标

#### 6.2.2 智能结算页（Settlement）

**页面构成：**

| 区域 | 内容 | 交互 |
|------|------|------|
| 扫码区（左侧上方） | 条码输入框 + 模拟扫码按钮 | 输入框自动聚焦，回车触发查询 |
| 商品展示区 | 扫码后展示商品信息（名称、条码、零售价、会员价） | 动画展开显示 |
| 促销方案区 | 展示所有匹配的促销方案卡片，含类型标签、规则、价格对比 | 点击卡片选中/取消，单选模式 |
| 操作按钮行 | "添加到购物车" + "跳过促销" | 选中方案后添加按钮激活 |
| 购物车面板（右侧） | 商品列表、数量、单价、合计、优惠、应付 | 实时更新 |
| 结算按钮 | "确认结算" | 购物车非空时激活 |

**页面逻辑：**
1. 页面加载时输入框自动聚焦，等待扫码枪输入
2. 扫码后：清空上一次的方案区 → 展开商品信息 → 延迟200ms展开促销方案区
3. 促销方案卡片单选，选中后卡片边框高亮为accent色，显示对勾标记
4. 点击"添加到购物车"：记录商品+选中方案+计算后价格 → 重置扫码区和方案区 → 更新购物车
5. 点击"跳过促销"：按原价(若识别到会员则用会员价)直接加入购物车
6. 满减类促销在购物车底部实时显示进度提示："当前累计¥XX，还差¥YY即可减¥ZZ"
7. 确认结算前弹出二次确认弹窗，显示应付金额
8. 结算完成后：扣减库存 → 记录流水 → 清空购物车 → 显示成功Toast → 触发库存阈值检测

#### 6.2.3 库存管理页（Inventory）

**页面构成：**

| 区域 | 内容 | 交互 |

| 工具栏 | 搜索框 + 状态筛选标签（全部/缺货/偏低/充足）+ 导出按钮 | 搜索实时过滤，标签切换筛选 |
| 库存表格 | 条码、商品名、分类、当前库存、安全阈值、状态标签、库存量进度条、促销标签、操作按钮 | 表头可排序（未来） |
| 操作列 | "补货"按钮/ "详情"按钮 | 补货→弹出补货弹窗，详情→展开商品详情 |

**页面逻辑：**

### 8.1 性能要求

| 数据导入 | ≤ 10秒/1000条 | 1000条记录导入完成时间 |

### 8.2 可用性要求

| 指标 | 要求 |

## 9. 风险与约束

### 9.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| AI绘画API不稳定/延迟高 | 海报生成超时或失败 | 设置合理超时+重试机制；缓存已生成结果；支持离线降级（提示稍后重试） |
| 扫码枪兼容性差异 | 部分扫码枪输入格式不标准 | 支持条码格式正则匹配与清洗；提供手动输入作为后备 |
| 促销规则复杂度爆炸 | 多促销叠加可能导致计算错误或性能下降 | 限制可叠加促销数量（默认最多3条）；规则引擎分层处理；充分的单元测试覆盖 |
| 数据导入格式不规范 | 用户上传的Excel格式各异 | 提供标准模板下载；灵活的列名映射；清晰的错误提示 |

### 9.2 业务风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 库存数据不准确 | 仅靠导入更新库存，中间的实物损耗/赠品/退货无法反映 | 支持手动库存调整功能；定期建议盘点 |
| 促销配置错误 | 错误的促销规则导致价格异常 | 促销新建需二次确认；配置完成后提供模拟计算功能（未来） |
| 操作员误操作 | 选错促销/误删商品 | 购物车操作支持撤销；结算前二次确认 |

### 9.3 约束条件

| 约束 | 说明 |
|------|------|
| 初始数据依赖 | 系统上线前必须完成三张基础表的首次导入 |
| 网络依赖（AI模块） | 海报生成需要网络连接AI API |
| 单店部署 | V1.0 版本为单店独立部署，不支持多店联网 |
| 人工结算 | 系统不对接支付渠道，仅计算金额，实际收款由操作员在外部完成 |
