# 中石油加油站智能零售系统项目落地与收银使用说明书

## 1. 文档目的

本文档用于指导加油站一线收银人员、站长和运营人员落地使用「中石油加油站智能零售系统」。收银员只需要掌握收银结算页面的日常操作；站长和运营人员负责数据导入、规则确认、库存预警和异常处理。

系统核心原则：前端页面只负责录入订单、展示后端计算结果和确认结算；促销是否可用、优惠金额、最终应付金额都由后端统一计算。

## 2. 使用对象与权限

### 收银员

可使用：

- 收银结算
- 扫码录入商品
- 调用促销计算
- 查看推荐方案、不可用促销原因
- 确认结算、打印小票

不可操作：

- 修改促销规则
- 导入 Excel 数据
- 人工改优惠金额
- 人工判断促销是否命中

### 站长

可使用：

- 收银结算
- 运营看板
- 库存预警
- AI 海报

主要职责：

- 查看门店促销执行情况
- 查看低库存、缺货商品
- 组织收银员培训
- 发现异常后反馈运营或管理员

### 运营人员

可使用：

- 收银结算
- 运营看板
- 数据导入
- 库存预警
- 规则管理
- AI 海报

主要职责：

- 导入价格、库存、活动看板等数据
- 确认促销规则
- 查看导入异常
- 维护活动物料和海报

## 3. 系统启动与访问

### 一键启动

在项目根目录双击：

```text
start-all.bat
```

脚本会自动执行：

- 启动 PostgreSQL 数据库容器
- 启动后端服务
- 启动前端页面
- 自动打开收银结算页面

默认访问地址：

```text
http://127.0.0.1:5173/checkout
```

后端健康检查地址：

```text
http://127.0.0.1:18082/actuator/health
```

### 页面右上角连接状态

右上角和底部会显示后端连接状态：

- 绿色圆点 + 已连接：系统正常，可以进行促销计算
- 红色圆点 + 未连接：前端已打开，但后端服务不可用

如果显示“未连接”，收银员不要继续结算促销，应按以下顺序处理：

1. 等待 10 秒并刷新页面。
2. 确认后端窗口是否仍在运行。
3. 重新双击 `start-all.bat`。
4. 若仍未连接，联系站长或技术人员。

## 4. 收银员每日标准操作流程

### 上岗前检查

收银员上岗前必须确认：

1. 页面已打开到“收银结算”。
2. 右上角显示“已连接”。
3. 左侧角色为“收银员”。
4. 页面底部显示规则版本，例如“规则版本: V22, 247 条 CONFIRMED”。
5. 鼠标光标位于“扫描或输入商品条码”输入框。

未满足以上条件时，不要开始使用系统处理促销结算。

### 标准结算流程

一次完整结算按以下步骤执行：

1. 扫描商品条码。
2. 确认商品进入购物车。
3. 如有多个商品，继续扫码。
4. 如商品数量不正确，在购物车中修改数量。
5. 如顾客有会员、油品、券等信息，确认订单上下文。
6. 点击“计算促销”。
7. 查看右侧“推荐方案”和“顾客到手价”。
8. 向顾客确认到手价和赠品、赠券。
9. 点击“选择此方案”完成确认结算。
10. 如需要小票，点击“打印”。
11. 点击“清空”或开始下一单。

收银员不需要判断哪条促销可用，只需要以系统推荐方案为准。

## 5. 收银结算页面说明

### 商品录入区

商品录入区用于扫码或手动录入商品。

推荐使用方式：

- 扫码枪扫码后自动回车
- 条码有效时商品自动加入购物车
- 同一商品重复扫码时，购物车数量自动增加

手动录入仅用于特殊情况，例如扫码枪故障或条码无法识别。

### 示例按钮

页面提供示例按钮：

- 9.9 固定价
- 满减
- 买赠
- 赠券
- 组合包
- 加油换购
- 无促销原价

示例按钮主要用于培训和演示。正式收银时应优先使用扫码枪录入真实商品。

### 购物车

购物车显示当前订单商品，包括：

- 商品名称
- 商品编码
- 条码
- 品类
- 单价
- 数量

收银员可以操作：

- 修改数量
- 删除误扫商品
- 清空当前订单

注意：购物车中的单价来自后端或商品资料，不允许收银员手工改最终优惠价。

### 订单上下文

订单上下文包括站点、会员、油品、券等信息。

常见使用场景：

- 顾客是会员：勾选会员并确认会员等级
- 顾客有券：录入券 ID 或已选券 ID
- 顾客参与加油换购：录入油品类型、油品牌号、油品金额或升数
- 站点省区默认使用当前门店所在省区

如果不确定某项信息，应保持默认值并联系站长确认。

## 6. 促销计算结果说明

点击“计算促销”后，右侧会显示后端返回结果。

### 推荐方案

推荐方案是系统根据后端规则计算出的最优或优先方案。

收银员重点看：

- 顾客到手价
- 已优惠金额
- 赠品
- 赠券
- 方案说明

顾客询问优惠原因时，可以按照系统显示的解释文本说明。

### 顾客到手价

黄色区域显示“顾客到手价”，这是收银员和顾客最需要关注的金额。

要求：

- 以页面显示金额为准
- 不要口算优惠
- 不要手工修改金额
- 如金额与顾客预期不一致，先查看不可用促销原因

### 可用促销方案

系统可能返回多个可用方案。默认选中推荐方案。

收银员一般不需要切换方案。只有在站长或运营明确要求，或顾客选择不使用某个优惠时，才选择其他方案。

### 原价兜底

如果顾客不参加促销，或所有促销都不可用，可以选择“原价兜底”。

原价兜底由后端返回，作用是保证每一单都有可确认的结算方案。

### 不可用促销

不可用促销会显示活动名称和原因，例如：

- 商品不满足活动范围
- 不满足金额门槛
- 活动规则未确认
- 库存或赠品条件不足
- 券不可用

收银员只负责解释页面显示的原因，不需要自行判断促销规则。

## 7. 常见收银场景

### 场景一：普通商品促销

1. 扫描商品。
2. 商品进入购物车。
3. 点击“计算促销”。
4. 查看推荐方案。
5. 向顾客确认到手价。
6. 点击“选择此方案”。

### 场景二：同一商品购买多件

1. 连续扫描同一商品条码。
2. 查看购物车数量是否正确。
3. 如数量错误，直接在数量框中修改。
4. 点击“计算促销”。

### 场景三：买赠活动

1. 扫描参与活动的商品。
2. 点击“计算促销”。
3. 查看推荐方案中是否有“赠品”标签。
4. 按页面显示发放赠品。
5. 确认结算。

### 场景四：赠券活动

1. 扫描商品。
2. 点击“计算促销”。
3. 查看推荐方案中的“赠券”信息。
4. 告知顾客券名称、金额和数量。
5. 确认结算。

### 场景五：加油换购

1. 扫描换购商品。
2. 在订单上下文填写油品类型、油品牌号、油品金额或升数。
3. 点击“计算促销”。
4. 查看是否返回换购方案。
5. 确认顾客到手价。

### 场景六：顾客不想参加促销

1. 点击“计算促销”。
2. 在右侧选择“原价兜底”。
3. 点击“选择此方案”。
4. 按原价完成结算。

## 8. 异常处理

### 页面显示未连接

处理方式：

1. 刷新页面。
2. 查看后端窗口是否运行。
3. 重新执行 `start-all.bat`。
4. 通知站长。

未连接时不要点击“计算促销”，否则会出现接口调用失败。

### 条码查询失败

可能原因：

- 商品资料未导入
- 条码录入错误
- 商品未在当前价格表中
- 后端接口异常

处理方式：

1. 检查条码是否扫错。
2. 重新扫码。
3. 仍失败时联系站长或运营。
4. 不要自行编造商品编码。

### 点击计算促销失败

可能原因：

- 后端未连接
- 购物车数据异常
- 数据库不可用
- 活动数据未导入

处理方式：

1. 查看页面错误提示。
2. 确认购物车不为空。
3. 确认页面右上角为“已连接”。
4. 重新点击一次。
5. 仍失败时联系站长。

### 顾客认为优惠不对

处理方式：

1. 查看“推荐方案”的解释文本。
2. 展开“不可用促销”查看原因。
3. 不要口头承诺系统外优惠。
4. 如仍有争议，暂停该单并联系站长处理。

### 商品数量录错

处理方式：

1. 在购物车数量框中修改数量。
2. 重新点击“计算促销”。
3. 以重新计算后的结果为准。

### 误扫商品

处理方式：

1. 在购物车中点击删除。
2. 确认购物车无误。
3. 重新点击“计算促销”。

## 9. 站长与运营落地流程

### 上线前准备

上线前需确认：

1. 服务器或收银电脑已安装 Java、Maven、Node.js、Docker。
2. `start-all.bat` 可以正常启动。
3. 前端页面可以打开。
4. 后端健康检查返回 `UP`。
5. 数据库 PostgreSQL 正常运行。
6. 已导入价格、库存、活动看板等基础数据。
7. 促销规则已确认到 CONFIRMED 状态。
8. 收银员已完成培训。

### 数据导入

运营人员进入“数据导入”页面：

1. 选择导入类型。
2. 上传 Excel 文件。
3. 点击“开始导入”。
4. 查看导入历史。
5. 如有异常，查看异常明细。

注意：

- 前端不解析 Excel。
- 不要修改 `data/` 原始 Excel 文件。
- 导入异常必须处理，不得跳过。

### 规则管理

运营人员进入“规则管理”页面：

1. 查看 DRAFT 规则。
2. 打开规则详情。
3. 查看条件 JSON、动作描述和审计日志。
4. 确认无误后点击“确认”。
5. 已确认但不再使用的规则可点击“停用”。

只有 CONFIRMED 规则参与收银结算。

### 库存预警

站长或运营进入“库存预警”页面：

1. 按预警级别筛选。
2. 查看缺货、低库存、关注商品。
3. 生成补货清单。
4. 导出 Excel。
5. 安排补货。

预警级别说明：

- 红色：缺货
- 橙色：低库存
- 黄色：需要关注
- 灰色：活动商品本站无库存

## 12. 日常运维要求

### 每日开班

站长或值班人员执行：

1. 启动系统。
2. 检查连接状态。
3. 用示例单测试一次“计算促销”。
4. 确认库存预警是否有红色缺货。

### 每日交班

收银员执行：

1. 完成当前订单。
2. 不要保留未确认购物车。
3. 关闭浏览器页面。
4. 交接异常订单和顾客反馈。

### 数据维护

运营人员执行：

1. 活动更新前导入新数据。
2. 导入后处理异常。
3. 确认规则。
4. 通知门店上线时间。

## 13. 禁止事项

收银人员禁止：

- 手工计算优惠金额
- 口头承诺系统未显示的优惠
- 修改规则 JSON
- 使用非系统推荐金额结算
- 未连接状态下继续尝试促销结算
- 私自修改原始 Excel 数据

运营人员禁止：

- 跳过导入异常
- 未确认规则就通知门店上线
- 在不了解规则影响时停用 CONFIRMED 规则

## 14. 快速故障定位表

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 页面打不开 | 前端未启动 | 重新运行 `start-all.bat` |
| 显示未连接 | 后端未启动或健康检查失败 | 检查后端窗口和 `/actuator/health` |
| 扫码无商品 | 商品资料缺失或条码错误 | 重新扫码，仍失败则联系运营 |
| 计算促销失败 | 后端接口异常或购物车数据异常 | 查看错误提示，重新计算 |
| 无推荐促销 | 规则不满足或未确认 | 查看不可用促销原因 |
| 到手价争议 | 顾客预期与规则不一致 | 以系统展示为准，联系站长 |
| 赠品未显示 | 后端未返回赠品 | 不得私自赠送，联系站长 |
| 库存预警为空 | 暂无预警或接口异常 | 刷新页面，联系运营确认 |

## 15. 一线话术建议

### 解释优惠

“系统已经按当前门店活动自动计算，这一单推荐方案是页面显示的这个到手价。”

### 解释不满足活动

“这条活动系统显示当前订单不满足条件，我可以请站长帮您核对一下活动规则。”

### 解释赠品或赠券

“系统显示本单赠送这个赠品/赠券，我按页面结果给您发放。”

### 解释系统异常

“系统连接暂时异常，我先请站长处理，避免给您算错优惠。”

## 16. 收银员上手标准

收银员满足以下条件即可独立上岗：

1. 能识别“已连接”和“未连接”。
2. 能独立完成扫码、改数量、删除商品。
3. 能独立点击计算促销并读出到手价。
4. 能查看推荐方案、赠品、赠券。
5. 能选择原价兜底。
6. 能处理误扫和数量错误。
7. 能在异常时停止操作并通知站长。

## 17. 总结

本系统落地后，收银员只需要遵循“扫码、计算、确认”的最短路径。促销判断、优惠金额和最终应付金额由后端统一计算，收银员以页面结果为准，不做人工判断。站长负责日常检查和异常协调，运营负责数据导入、规则确认和活动维护。
