## 1. 产品概述

### 1.1 产品定位

加油站智能零售促销系统是面向加油站便利店场景的一体化智能运营管理终端系统，通过多源数据融合（商品价格表、促销政策表、库存数量表），实现**智能促销结算、库存动态预警、会员精准营销**三大核心能力，解决传统收银系统在促销匹配效率、库存响应速度和会员营销精准度上的痛点。

### 1.2 目标用户

| 用户群体 | 典型角色 | 使用场景 | 核心诉求 |
|---------|---------|---------|---------|
| 门店前台 | 收银员 | 日常收银结算 | 快速扫码、正确执行促销、零学习成本 |
| 门店管理 | 店长/副店长 | 运营管理、补货决策 | 库存一目了然、补货流程自动化 |
| 区域运营 | 运营主管 | 多门店策略配置 | 促销政策统一配置、跨门店数据对比 |
| 系统维护 | IT管理员 | 系统部署与配置 | 数据导入、权限管理、系统稳定性 |

### 1.3 解决的核心问题

| 痛点 | 现状 | 解决方案 |
|------|------|---------|
| 促销结算慢、易出错 | 收银员凭记忆或翻阅纸质文件核对促销 | 条码扫描后自动匹配所有适用促销方案，一键选择 |
| 促销规则复杂多样 | 活动看板包含9大类促销，规则叠加复杂 | 规则引擎统一处理，支持多种促销类型和叠加逻辑 |
| 促销与库存脱节 | 活动商品池不等于本站库存，易断货 | 实时监控促销商品库存，低库存强制预警 |
| 会员营销粗放 | 不同会员等级优惠方式不一致 | 会员等级体系 + 会员专享促销 + 精准赠券 |
| 油非互促结算复杂 | 加油换购涉及跨品类、跨订单项判断 | 统一规则引擎处理油品+非油组合促销 |

## 4. 核心业务流程

### 4.1 智能结算流程

```
收银员扫描商品条码
        │
        ▼
┌─────────────────┐
│  查询商品价格表   │ → 获取商品信息、执行价、会员价
└────────┬────────┘
         ▼
┌─────────────────┐
│  查询库存快照    │ → 获取当前库存、判断是否低库存
└────────┬────────┘
         ▼
┌─────────────────┐
│ 构建订单上下文   │ → 商品列表、数量、会员信息、油品消费
└────────┬────────┘
         ▼
┌─────────────────┐
│ 规则引擎匹配     │ → 筛选有效规则、计算候选方案、处理互斥叠加
└────────┬────────┘
         ▼
┌─────────────────────────────────┐
│  界面展示所有可选促销方案卡片      │
│  每张卡片显示:                    │
│  - 促销名称与类型标签             │
│  - 规则简述                      │
│  - 原价 → 实付价                 │
│  - 节省金额                      │
│  - 库存预警提示                  │
│  - 会员专享标识                  │
└────────┬────────────────────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌───────┐ ┌───────┐
│选择方案 │ │ 跳过   │
└───┬───┘ └───┬───┘
    │         │
    ▼         ▼
┌───────────────┐
│ 加入购物车     │ ← 记录: 商品、数量、适用促销、计算后单价
│ 更新小计/总计  │
│ 更新满减累计   │ ← 实时计算满减进度
└───────┬───────┘
        │
        ▼ (所有商品扫完后)
┌───────────────┐
│ 显示交易汇总   │ ← 商品合计、各优惠明细、优惠总额、应付金额
│ 显示赠券提示   │ ← 满额赠券、会员赠券
└───────┬───────┘
        ▼
┌───────────────┐
│ 确认结算       │ → 扣减库存 → 记录交易流水 → 发放赠券 → 清空购物车
└───────────────┘
```

### 4.2 加油换购流程

```
输入或获取油品消费
        │
        ▼
┌─────────────────┐
│ 识别油品类型和金额 │ → 汽油/柴油/CNG/LNG
└────────┬────────┘
         ▼
┌─────────────────┐
│ 扫描换购商品     │ → 识别组合包或单品
└────────┬────────┘
         ▼
┌─────────────────┐
│ 匹配换购规则     │ → 检查油品金额门槛、换购价、库存
└────────┬────────┘
         ▼
┌─────────────────┐
│ 展示换购方案     │ → 组合包内容、换购价、优惠金额
└────────┬────────┘
         ▼
┌─────────────────┐
│ 确认执行        │ → 扣减库存 → 记录换购明细
└─────────────────┘
```

### 4.3 会员券核销流程

```
识别会员身份
        │
        ▼
┌─────────────────┐
│ 查询可用券列表   │ → 显示券面额、使用门槛、有效期
└────────┬────────┘
         ▼
┌─────────────────┐
│ 选择使用的券     │ → 可多选，按规则判断是否可叠加
└────────┬────────┘
         ▼
┌─────────────────┐
│ 计算优惠后金额   │ → 券抵扣 + 其他促销
└────────┬────────┘
         ▼
┌─────────────────┐
│ 更新券状态      │ → 已使用/已过期
└─────────────────┘
```

### 4.4 库存预警与补货流程

```
系统持续监控库存
        │
        ▼
┌─────────────────┐
│ 比对库存 vs 阈值 │ → 促销商品阈值自动提升
└────────┬────────┘
         ▼
┌─────────────────┐
│ 判断预警级别     │ → critical: ≤阈值×20%, warning: ≤阈值
└────────┬────────┘
         ▼
┌─────────────────┐
│ 强制弹窗预警     │ → 促销商品不可关闭，必须确认
└────────┬────────┘
         ▼
┌─────────────────┐
│ 生成补货清单     │ → 建议补货量 = 阈值×2 - 当前库存
└────────┬────────┘
         ▼
┌─────────────────┐
│ 一键导出        │ → Excel/CSV格式
└─────────────────┘
```

## 6. 促销规则引擎设计

### 6.1 规则模型

```text
规则 = 触发条件 + 适用范围 + 优惠动作 + 限制条件 + 优先级 + 互斥组
```

### 6.2 触发条件

| 条件类型 | 字段 | 说明 |
|---------|------|------|
| 时间条件 | daysOfMonth | 指定日期触发（如每月9日） |
| | startDate / endDate | 日期范围 |
| 油品条件 | fuelTypes | 油品类型（汽油/柴油/CNG/LNG） |
| | minFuelAmount | 油品金额门槛 |
| | minFuelVolume | 油品升数门槛 |
| 商品条件 | productCodes | 指定商品编码 |
| | includedCategories | 包含品类 |
| | excludedCategories | 排除品类（香烟、化肥） |
| 购物车条件 | minCartAmount | 购物车金额门槛 |
| 会员条件 | memberRequired | 是否需要会员 |
| | memberLevels | 适用会员等级 |
| | birthdayMonthRequired | 是否生日月 |
| 站点条件 | stationTypes | 站点类型（加油站/加气站） |

### 6.3 优惠动作

| 动作类型 | 说明 | 数据结构 |
|---------|------|---------|
| FIXED_PRICE | 固定价格 | `fixedPrice: BigDecimal` |
| PERCENTAGE_DISCOUNT | 百分比折扣 | `discountRate: BigDecimal` |
| AMOUNT_OFF | 金额立减 | `amountOff: BigDecimal` |
| EXCHANGE_PURCHASE | 加油换购 | `exchangePrice: BigDecimal, bundleItems: List` |
| GIFT_ITEM | 买赠 | `giftItemCode: String, giftItemQuantity: int` |
| GIFT_COUPON | 赠券 | `giftCouponTiers: List` |
| BUNDLE_PRICE | 组合包 | `bundleId: String, bundlePrice: BigDecimal` |
| COUPON_REDEEM | 券核销 | - |
| FUEL_VOLUME_DISCOUNT | 油品立减 | `discountPerUnit: BigDecimal` |

### 6.4 叠加与互斥规则

#### 6.4.1 叠加规则

| 促销类型 | 可叠加对象 | 说明 |
|---------|-----------|------|
| 油品立减 | 油品消费赠券 | 立减后仍可获得赠券 |
| 全场折扣 | 会员权益包 | 折扣后仍可使用权益包内券 |
| 满减 | 赠券 | 满减后可使用赠券 |
| 加油换购 | 油品赠券 | 换购同时可获得油品赠券 |
| 买赠 | 积分加倍 | 买赠商品仍可获得加倍积分 |

#### 6.4.2 互斥规则

| 互斥组 | 包含促销类型 | 说明 |
|--------|------------|------|
| direct_discount | 固定价、百分比折扣、金额立减 | 同一商品只能选择一种直接降价 |
| exchange_purchase | 组合包换购、单品换购 | 同一订单只能选择一种换购方式 |
| gift_coupon | 油品赠券、满赠券、会员券 | 同一类型券不可重复获得 |
| member_price | 会员专享价、普通会员价 | 取最优价 |

### 6.5 优先级排序规则

1. 用户已选择的促销（手动选择优先）
2. 强制规则（如会员生日券必须使用）
3. 到手价最低的方案
4. 优惠金额最大的方案
5. 赠券价值最高的方案
6. 毛利率合规的方案（低于底线的方案禁用）
7. 库存充足的方案（低库存方案降级）
8. 活动优先级高的方案

## 7. 会员体系设计

### 7.1 会员数据模型

```text
会员 (Member)
    ├── 会员编号 (memberCode)
    ├── 会员姓名 (memberName)
    ├── 手机号 (phone)
    ├── 会员等级 (level) → 关联会员等级表
    ├── 累计积分 (totalPoints)
    ├── 可用积分 (availablePoints)
    ├── 生日 (birthday)
    ├── 所在省份 (province)
    └── 状态 (status)

会员等级 (MemberLevel)
    ├── 等级编码 (levelCode)
    ├── 等级名称 (levelName)
    ├── 会员折扣率 (discountRate)
    ├── 积分倍率 (pointsMultiplier)
    ├── 升级最低消费 (minConsumption)
    └── 权益列表 (benefits)
```

### 7.2 会员与促销的关联逻辑

#### 7.2.1 会员价计算

```text
会员价 = 执行价 × 会员折扣率
最终价 = min(会员价, 促销价)
```

#### 7.2.2 积分计算

```text
获得积分 = 实付金额 × 积分倍率
```

#### 7.2.3 生日月优惠

- 会员生日当月自动匹配生日专属促销
- 生日券自动发放到会员账户

## 8. 数据导入与管理

### 8.1 导入流程

```text
选择文件 → 解析工作表 → 数据清洗 → 校验 → 预览 → 导入确认 → 生成规则
```

### 8.2 数据清洗规则

| 规则 | 说明 |
|------|------|
| 合并单元格处理 | 向下填充空值，记录继承来源 |
| 商品编码标准化 | 转为字符串，去除".0"后缀 |
| 金额标准化 | 转为BigDecimal，去除逗号和百分号 |
| 日期标准化 | 统一转为LocalDate |
| 枚举映射 | 油品类型、站点类型映射为枚举值 |

### 8.3 校验规则

| 校验项 | 规则 | 处理方式 |
|--------|------|---------|
| 商品编码 | 必须在价格表中存在 | 错误，标记缺失 |
| 条码 | 唯一性校验 | 警告，标记重复 |
| 金额 | 必须大于0 | 错误，标记无效 |
| 日期范围 | 开始日期 ≤ 结束日期 | 错误，标记无效 |
| 毛利率 | 必须 ≥ 最低毛利率 | 警告，标记需审批 |
| 库存 | 促销商品需有库存 | 警告，标记低库存 |

## 12. 非功能需求

### 12.1 性能需求

| 指标 | 要求 |
|------|------|
| 扫码后商品查询 | ≤ 300ms |
| 常规促销匹配 | ≤ 1秒 |
| 多商品购物车促销计算 | ≤ 2秒 |
| 库存预警扫描 | 分钟级完成 |

### 12.2 可用性需求

| 指标 | 要求 |
|------|------|
| 前台扫码界面 | 简洁，适合高峰期快速操作 |
| 促销方案展示 | 默认展示推荐方案和关键差异 |
| 异常处理 | 允许原价结算，不能阻断收银业务 |
| 离线支持 | 核心结算功能离线可用 |

### 12.3 可扩展性需求

| 要求 | 说明 |
|------|------|
| 促销规则扩展 | 通过配置扩展，无需修改代码 |
| 新活动表模板 | 可配置映射 |
| 系统集成 | 支持后续接入POS、会员、电子券系统 |

### 12.4 准确性需求

| 要求 | 说明 |
|------|------|
| 价格准确性 | 必须以价格表或POS实时价格为准 |
| 促销价可追溯 | 每个优惠结果应能解释由哪条规则触发 |
| 库存预警 | 应标明数据更新时间 |

### 12.5 安全与合规需求

| 要求 | 说明 |
|------|------|
| 用户登录和权限控制 | 必须 |
| 接口密钥加密存储 | 必须 |
| 敏感信息脱敏 | 手机号等个人信息脱敏 |
| 操作日志不可随意删除 | 必须 |
