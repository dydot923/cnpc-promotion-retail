# 项目结构

本项目是加油站促销智能零售系统，当前以促销规则引擎、Excel 导入、规则治理、收银 checkout、库存预警和补货闭环为主线。

## 顶层目录

```text
.
|-- backend/                  Java 21 / Spring Boot 3 后端服务
|-- frontend/                 React 18 / TypeScript / Vite 前端
|-- data/                     原始业务数据源，只读使用
|-- docs/                     需求、设计、报告、执行记录和项目约束
|-- docker-compose.yml        本地 PostgreSQL 等基础设施
|-- README.md                 项目启动、接口契约和关键说明
|-- .agents/                  本地协作代理配置
|-- .codex-spreadsheet-work/  表格处理临时工作目录
|-- .gitignore
`-- .gitattributes
```

## 后端结构

后端代码主包位于 `backend/src/main/java/com/cnpc/promoretail`。

```text
backend/
|-- pom.xml
|-- README.md
`-- src/
    |-- main/
    |   |-- java/com/cnpc/promoretail/
    |   |   |-- ruleengine/       促销计算核心领域，保持业务计算集中
    |   |   |-- checkout/         收银计算、计算记录和确认闭环
    |   |   |-- promotion/        促销规则治理、规则管理、组合包、券和商品组
    |   |   |-- importcenter/     Excel 导入、批次记录和异常行处理
    |   |   |-- product/          商品查询、商品持久化模型
    |   |   |-- inventory/        库存查询、库存预警
    |   |   |-- replenishment/    补货清单生成、查询和导出
    |   |   |-- audit/            审计日志写入和查询
    |   |   |-- common/           通用 API、配置和持久化装配
    |   |   |-- price/            价格模块预留边界
    |   |   |-- auth/             认证模块预留边界
    |   |   `-- poster/           海报模块预留边界
    |   `-- resources/
    |       |-- application.yml
    |       `-- db/migration/     Flyway 数据库迁移脚本
    `-- test/
        `-- java/com/cnpc/promoretail/
```

### 后端边界

- `ruleengine` 是促销计算核心，包含条件匹配、权益计算、互斥处理、候选排序、解释文本和上下文模型。
- `checkout` 负责把订单上下文交给规则引擎，保存计算记录，并处理用户确认，不应把促销计算逻辑下沉到 controller。
- `promotion` 负责规则草稿、确认、拒绝、停用、规则版本和治理审计。
- `importcenter` 负责把 Excel 数据导入到结构化模型，导入异常通过批次和异常行记录追踪。
- `product`、`inventory`、`replenishment` 支撑商品检索、库存预警和补货闭环。
- `audit` 提供跨模块审计日志能力。
- `common` 放置全局异常处理、配置装配和通用基础设施。

### 迁移脚本约定

数据库迁移脚本位于 `backend/src/main/resources/db/migration`。已存在的 `V1__...` 到 `V16__...` 脚本应视为不可变历史；新增表结构或种子数据时继续追加 `V17__...`、`V18__...`，不要改写已执行版本。

## 前端结构

前端代码位于 `frontend/src`。

```text
frontend/
|-- package.json
|-- package-lock.json
|-- vite.config.ts
|-- tsconfig.json
|-- tsconfig.app.json
|-- tsconfig.node.json
|-- index.html
|-- README.md
|-- scripts/
|   `-- smoke-test.mjs
`-- src/
    |-- App.tsx
    |-- main.tsx
    |-- styles.css
    |-- types.ts
    |-- api/       后端接口客户端
    `-- pages/     页面级功能入口
```

### 前端边界

- `pages` 放页面级流程，如收银结算、规则确认、导入异常、库存预警、补货清单和审计日志。
- `api` 只封装后端接口调用，不承载促销可用性、互斥、应付金额、库存或会员判断。
- `types.ts` 放前端共享类型，接口契约以后端返回为准。

## 文档与数据

```text
docs/
|-- agents/          协作角色说明
|-- import-drafts/   导入草稿和数据缺口记录
|-- *.md             需求、架构、设计、测试、演示和治理文档
|-- *.txt
|-- *.json
`-- *.docx

data/
|-- 价格.xlsx
|-- 库存.xlsx
`-- 活动看板.xlsx
```

- `docs` 保存项目过程文档和交付说明，新增设计、验证、复盘类文档优先放这里。
- `docs/import-drafts` 专门放数据导入草稿、字段映射和缺口分析。
- `data` 中的 Excel 文件是原始业务数据源，只读使用，不移动、不删除、不修改。

## 推荐维护原则

- 保持前后端独立：后端负责业务判断和金额计算，前端负责录入、调用和展示。
- 保持规则引擎集中：新增促销条件或权益类型优先扩展 `ruleengine` 下的 matcher、calculator 或 model。
- 保持持久化边界清楚：业务服务依赖 repository 接口，数据库实现放到对应模块的 `persistence` 或 `repository` 包。
- 保持文档入口清楚：项目运行、接口契约和关键约束放根 `README.md`；细节设计和执行记录放 `docs`。
- 保持原始数据稳定：`data` 目录只读，派生结果应写入数据库、测试夹具或 `docs/import-drafts`。
