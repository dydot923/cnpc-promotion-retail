## 0. 重要目录约定

当前项目仓库中，原始 Excel 数据文件已经放在 `data/` 目录下。请优先读取并识别：

```text
data/活动看板.xlsx
data/价格.xlsx
data/库存.xlsx
```

这些 Excel 是本项目最重要的真实业务数据来源：

- `活动看板.xlsx`：促销活动、加油换购、非油促销、会员权益、9.9 专区、券适用范围等；
- `价格.xlsx`：商品编码、商品名称、商品条码、执行价；
- `库存.xlsx`：商品编码、商品名称、商品条码、本站库存数量。

不要假设 Excel 在其他目录。如果文件名略有差异，请先在 `data/` 目录下查找相近文件，并向我说明你识别到的文件。

## 3. 最高优先级

本项目一期必须优先完成 **促销智能计算引擎**。

不要先堆页面，不要先做海报，不要先做报表。促销计算引擎必须是系统的核心内核。

一期核心目标：

```text
把 data/ 下的真实 Excel 数据导入并结构化
基于商品、价格、库存、促销规则建立标准模型
实现 ruleengine 促销智能计算引擎
实现 checkout calculate 结算计算接口
用真实促销样例写测试
```

## 4. 必须遵守的架构约束

1. 促销逻辑只能集中在后端 `ruleengine` 模块。
2. 前端不得写促销判断逻辑。
3. Controller 不得写促销判断逻辑。
4. Service 只能做流程编排，不能堆大段促销 `if/else`。
5. 金额计算必须使用 `BigDecimal`，禁止使用 `double` 或 `float`。
6. 商品编码和条码必须使用 `String`。
7. 规则必须可解释、可测试、可版本追溯。
8. 不可用促销也要返回不可用原因，不能静默丢弃。
9. 原价结算必须始终可用。
10. Excel 导入必须生成异常报告，不能静默丢弃异常行。
11. AI 海报不能作为价格和促销文案的真相来源。
12. `data/` 目录下的 Excel 只作为原始数据源，导入后应形成结构化规则、商品、价格和库存数据。

### 第五步：支持一期核心促销类型

先支持：

1. `fixed_price`：固定促销价，例如 9.9 元专区；
2. `percentage_discount`：折扣，例如逢 9 全场 9 折；
3. `amount_off`：满减；
4. `exchange_purchase`：加油换购；
5. `gift_item`：买赠；
6. `gift_coupon`：赠券；
7. `bundle_price`：组合包价。

### 第六步：基于 data/ 真实 Excel 做导入设计

请设计并实现导入能力：

```text
POST /api/import/prices
POST /api/import/inventory
POST /api/import/promotions
```

导入要求：

- 使用 EasyExcel；
- 商品编码按 String 读取；
- 商品条码按 String 读取；
- 金额按 BigDecimal 读取；
- 合并单元格要处理；
- 空值继承要明确；
- 不可解析的自然语言规则进入“待确认”状态；
- 导入结果必须返回新增、更新、跳过、异常数量；
- 异常行必须可导出或可查看；
- 不得静默覆盖人工修正规则。

### 第七步：为促销引擎写单元测试

测试必须覆盖：

- 9.9 元固定价；
- 逢 9 全场 9 折；
- 香烟、化肥排除；
- 汽油满额换购；
- 柴油满额换购；
- 买赠；
- 赠券；
- 组合包；
- 库存不足；
- 油品金额不足；
- 多促销互斥；
- 原价兜底；
- 不可用原因返回。

### 第八步：实现结算计算接口


- 不可用促销及原因；
- 解释文本；
- 规则版本；
- 库存警告；
- 原价兜底方案。

不要反过来。
