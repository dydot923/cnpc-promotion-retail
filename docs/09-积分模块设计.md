# 积分模块设计

## 1. 模块归属

积分累计、积分兑换、积分抽奖属于会员积分系统，不属于 checkout 促销价格计算核心。checkout 只接收后端计算后的展示字段，不在前端计算积分。

## 2. 核心模型

| 模型 | 字段 |
|---|---|
| PointPolicy | policyId、activityCode、fuelTypes、categories、multiplier、startDate、endDate、status、version |
| PointLedger | ledgerId、memberId、orderId、pointsDelta、sourceActivityCode、occurredAt |
| PointBalance | memberId、availablePoints、frozenPoints、updatedAt |
| PointRedemption | redemptionId、memberId、pointsUsed、couponTemplateId、status |

## 3. 与 checkout 的边界

- checkout 可以返回 `pointsMultiplier`、`pointsEarned`、`pointPolicyVersion`。
- 积分不能改变 `payableAmount`，除非未来接入“积分抵扣”规则；届时仍必须由后端 ruleengine 输出金额。
- 积分兑换 9 折优惠应先兑换为券或独立规则，再由 checkout 核销。

## 4. 活动映射

| 活动 | 策略 |
|---|---|
| A2 逢7气惠 | CNG/LNG 每消费 1 元积 3 分 |
| A5/G2 逢9便利店 | 会员消费便利店商品 3 倍积分 |
| G2 积分抽奖 | 500 积分抽 1 次，归积分活动系统 |

## 5. 风险

积分倍率和积分扣减必须写入积分流水，不能只存在订单快照；积分抽奖消耗也必须可追溯。
